### 1.3 Rôles Utilisateurs & Permissions (Acteurs)

> **Constat d'audit critique :** **Aucun système de rôles, d'authentification ou de contrôle d'accès (RBAC) n'est implémenté** ni côté backend ni côté frontend.

- Il n'existe ni entité `User`, ni rôle (`Admin`, `Demandeur`, `Responsable Achats`, `Magasinier`), ni garde de route.
- Tous les endpoints `/api/fournisseurs/**` et `/actuator/**` sont accessibles sans jeton ni session.
- **Acteur fonctionnel unique implicite :** l'application opère comme une console unique de gestion destinée au **Gestionnaire Achats / Administrateur Référentiel Fournisseurs** (référencé dans les libellés « Système Achats » et « VISA DU RESPONSABLE ACHATS » sur le dossier PDF). Cet acteur unique dispose de l'ensemble des actions UI et API : consultation, création, modification, import en masse, désactivation/réactivation logique, géocodage manuel, notation locale, export CSV/PDF et consultation de l'historique des commandes.

### 1.4 Modèles de Domaine & Relations

#### A. Entité Principale Persistance Locale : `Fournisseur` (`Fournisseur.java`, table `schema_fournisseurs.fournisseurs`)
- `id` (`Long`, `BIGINT GENERATED BY DEFAULT AS IDENTITY`, PK, non modifiable).
- `nom` (`String`, `VARCHAR(150) NOT NULL`, contrainte SQL `CHECK (length(btrim(nom)) > 0)`, trim automatique en `@PrePersist` / `@PreUpdate`).
- `email` (`String`, `VARCHAR(150) NOT NULL UNIQUE`, contrainte `fournisseurs_email_key`, normalisé `trim().toLowerCase(Locale.ROOT)` avant persistance).
- `telephone` (`String`, `VARCHAR(30)`, nullable ; chaînes vides/blancs converties en `null`).
- `adresse` (`String`, `TEXT`, nullable ; chaînes vides/blancs converties en `null`).
- `actif` (`Boolean`, `BOOLEAN NOT NULL DEFAULT TRUE`).
- `createdAt` (`OffsetDateTime`, `TIMESTAMPTZ NOT NULL`, UTC, non modifiable après création).
- `updatedAt` (`OffsetDateTime`, `TIMESTAMPTZ NOT NULL`, UTC, mis à jour à chaque `@PreUpdate`).

#### B. Objets de Transfert (DTO Backend & Types Frontend)
- `FournisseurRequest(nom, email, telephone, adresse)`
- `FournisseurResponse(id, nom, email, telephone, adresse, actif, createdAt, updatedAt)` (dates formatées `yyyy-MM-dd'T'HH:mm:ssXXX` UTC tronquées à la seconde).
- `PageResponse<T>(content, page, size, totalElements, totalPages, first, last, empty)`.
- `FournisseurStatsResponse(total, actifs, inactifs, tauxEligibilite, villes)`.
- `CommandeSummaryResponse` / `CommandeSummary` (DTO distant lu depuis le service Commandes) : `id`, `fournisseurId`, `dateCommande`, `statut`, `montantTotal`, `lignes: List<LigneCommandeSummaryDto(designation, quantite, prixUnitaire)>`.

#### C. Stockage Client Supplémentaire (`localStorage`, non persisté en PostgreSQL)
- `'procuraflow-supplier-ratings'` : `Record<number, number>` stockant les notes manuelles (`1.0` à `5.0`) saisies lors de la création/édition ou de l'import.
- `'procuraflow-exact-coords'` : cache des coordonnées géographiques validées via OpenStreetMap Nominatim (`{ addressNormalized, lat, lng, displayName, savedAt }`).
- `'procuraflow-theme'` : préférence `'dark'` | `'light'`.

#### D. Relations entre Entités (Multi-Schémas PostgreSQL dans `database/init.sql`)

```text
schema_fournisseurs.fournisseurs (1) <--- [fournisseur_id : lien logique inter-services] --- (N) schema_commandes.commandes
schema_commandes.commandes       (1) <--- [commande_id FK ON DELETE CASCADE] ------------- (N) schema_commandes.lignes_commande
schema_commandes.commandes       (1) <--- [commande_id : lien logique inter-services] ------ (N) schema_receptions.receptions
schema_commandes.commandes       (1) <--- [commande_id : lien logique inter-services] ------ (N) schema_factures.factures
schema_receptions.receptions     (0..1) <- [reception_id : lien logique] ------------------- (N) schema_factures.factures
```

*Note : aucune contrainte `FOREIGN KEY` SQL inter-schémas n'existe (couplage microservice par identifiant logique) ; la suppression physique d'un fournisseur est interdite et remplacée par une désactivation logique (`actif = false`) afin de préserver l'intégrité des commandes historiques.*

## 3. DETAILED SCREEN-BY-SCREEN / MODULE BREAKDOWN

L'application frontend est une **Single Page Application (SPA)** sans routeur URL (`ReactDOM` monte directement `App` sur `/` dans `main.tsx`). Toute la navigation s'effectue par changements d'état (vues, modales, tiroirs).

### 3.1 Écran Principal — Barre de Navigation & Bandeau Héro (`Navbar.tsx`, `App.tsx`)

- **Route / Contexte** : `/` (persistant en haut de l'application).
- **Composantes UI** :
  - Identité : Logo `ProcuraFlow`, fil d'Ariane `Fournisseurs`, badge titre `Répertoire des Fournisseurs` (« Gestion des Achats & Approvisionnements »).
  - Déclencheur Palette de commandes (`Rechercher...` avec badge `Ctrl+K`).
  - Switch thème (`role="switch"`, Clair / Sombre).
  - Indicateur d'état API (`API Connectée` / `API Déconnectée` / état initial).
  - Bouton bascule `Mode Démo` / Mode API Réel.
- **Actions & Traitements** :
  - Clic `Rechercher...` ou `Ctrl+K` / `Cmd+K` : ouvre `CommandPalette`.
  - Clic Switch Thème : bascule la classe `dark` sur `<html>` et `<body>`, persiste dans `localStorage['procuraflow-theme']`, affiche un Toast.
  - Clic Indicateur API : exécute `checkHealth()` -> `GET /actuator/health`.
  - Clic `Mode Démo` : bascule `demoMode`, réinitialise le cache `fetchedOrderStatsIdsRef`, remet `page = 0`, bascule la source de données vers `INITIAL_MOCK_FOURNISSEURS` (16 fournisseurs) + `MOCK_COMMANDES` en mémoire locale.

### 3.2 Tableau de Bord KPI (`StatsBar.tsx`)

- **Route / Contexte** : `/` (section supérieure au-dessus de la barre d'outils).
- **Composantes & Données affichées** (issues de `GET /api/fournisseurs/stats` ou `computeDemoGlobalStats` en Mode Démo — **toujours globales**, jamais limitées à la page courante) :
  1. **Carte 1 — `TOTAL FOURNISSEURS`** : valeur `stats.total`, sous-libellé `Répertoire global`.
  2. **Carte 2 — `FOURNISSEURS ACTIFS`** : valeur `stats.actifs`, sous-libellé `Commandes autorisées`.
  3. **Carte 3 — `FOURNISSEURS INACTIFS`** : valeur `stats.inactifs`, sous-libellé `Désactivés`.
  4. **Carte 4 — `TAUX D'ÉLIGIBILITÉ`** : valeur `stats.tauxEligibilite` `%`, barre de progression visuelle, sous-libellé `{actifs} sur {total} fournisseurs` (et si `demoMode && avgRating !== null`, note moyenne du catalogue démo).
- **Règles de calcul Backend (`FournisseurService.getGlobalStats`)** :
  - `tauxEligibilite = total == 0 ? 0 : (int) Math.round((actifs * 100.0) / total)`.
  - `villes` : extraction de la ville depuis les adresses non nulles, normalisation + déduplication avec `Collator` français (`Collator.PRIMARY`).
- **Actions** :
  - Clic sur Carte 1 (`TOTAL`) -> applique `statusFilter = 'all'`, `page = 0`.
  - Clic sur Carte 2 (`ACTIFS`) -> applique `statusFilter = 'active'`, `page = 0`.
  - Clic sur Carte 3 (`INACTIFS`) -> applique `statusFilter = 'inactive'`, `page = 0`.

### 3.4 Vues Liste (`FournisseurTable.tsx`) & Cartes (`FournisseurCards.tsx`) + Pagination (`PaginationBar.tsx`)

- **Colonnes du Tableau (`FournisseurTable`)** :
  1. `Fournisseur` : Avatar initiales + `nom` + `ID: #{id}`.
  2. `Coordonnées` : `email` + bouton copier, `telephone` (ou « Téléphone non renseigné ») + bouton copier.
  3. `Adresse` : `adresse` (ou « Adresse non renseignée ») + bouton copier.
  4. `Évaluation` : 5 étoiles visuelles + `rating.score.toFixed(1)` (calculé par `computeSupplierRating`).
  5. `Statut` : badge `Actif` (point vert animé) ou `Inactif` (badge gris).
  6. `Actions` : bouton `Commandes` (avec compteur et infobulle financière si `orderStats[id]` chargé), bouton `Modifier`, bouton `Désactiver` / `Réactiver`.
- **Éléments supplémentaires de la Vue Cartes (`FournisseurCards`)** :
  - Grille responsive 1 à 4 colonnes affichant : avatar, nom, `#id`, badge statut, bandeau scoring (`score / 5.0`, `fiabilitePct%`, `statusLabel` : `Recommandé` / `Conforme` / `Sous surveillance` / `Inactif`), email/téléphone/adresse avec copie, encadré KPI achats (`Total Commandé`, `Total Engagé`, `Commandes`, `Dernière Cde`), et boutons d'action en pied de carte.
- **Chargement paresseux des commandes (`App.tsx`)** : pour chaque fournisseur visible sur la page et non encore en cache (`fetchedOrderStatsIdsRef`), un appel `GET /api/fournisseurs/{id}/commandes` est lancé en parallèle sans bloquer la page (les erreurs `:8082` sont ignorées silencieusement sur la vue liste).
- **Contrôles de Pagination (`PaginationBar`, sous Liste et Cartes)** :
  - Indicateur : `Affichage X–Y sur Z fournisseur(s)` + `Page P sur T`.
  - Sélecteur `Par page :` (`<select>`) : `10` (défaut), `25`, `50`. Changer la taille remet `page = 0`.
  - Boutons `Précédent`, numéros de page (`1`-indexés en UI, `0`-indexés en API) avec ellipses (`...` lorsque `totalPages > 7`), et `Suivant`. Désactivés sur la première/dernière page et pendant `loading`.
  - Si la page demandée dépasse `totalPages` après une mutation/filtrage, `App.tsx` recale automatiquement sur `totalPages - 1`.

### 3.5 Vue Carte Interactive (`FournisseurMap.tsx`, `geoLocation.ts`)

- **Chargement** : Lazy-load via `React.lazy` ; lorsque `viewMode === 'map'`, déclenche `GET /api/fournisseurs` **non paginé** avec les filtres/tri actifs.
- **Composantes UI** :
  - Légende avec compteurs : `Position exacte` (cercle teal plein), `Approx. par ville` (cercle bleu pointillé), `Non localisés` (bouton ouvrant/fermant le tiroir latéral droit `Sans localisation`).
  - Boutons carte : `Maroc` (recadre sur `[31.7917, -7.0926]`, zoom `6`), `Tout voir` (`fitBounds` sur tous les marqueurs), sélecteur de tuiles (`Auto`, `OSM` OpenStreetMap, `Sombre` CartoDB Dark All).
  - Carte Leaflet + `MarkerClusterGroup` (`maxClusterRadius: 42`, `spiderfyOnMaxZoom: true`).
  - **Popup DOM sécurisée** (construite via `document.createElement` + `textContent`, sans `innerHTML` sur données utilisateur) : nom, `#id`, badge statut, précision, adresse, boutons `Commandes`, `Modifier`, et bouton manuel `Localiser via OSM` (si non exact).
  - **Tiroir latéral `Sans localisation`** : liste les fournisseurs non géolocalisés avec bouton `Éditer adresse` et bouton `OSM` (géocodage unitaire).
- **Règles de résolution géographique (`resolveSupplierLocation`)** — Aucune coordonnée n'est inventée :
  1. Champs explicites `latitude` / `longitude` valides (dans `[-90,90]` / `[-180,180]`, hors `(0,0)`).
  2. Cache `localStorage['procuraflow-exact-coords']` si l'adresse normalisée correspond exactement à l'adresse sauvegardée.
  3. Extraction de coordonnées GPS écrites dans `adresse` via regex `/(-?\d{1,2}\.\d{4,})\s*[,;\s]\s*(-?\d{1,3}\.\d{4,})/g`.
  4. Gazetteer local de **74 villes** (30 marocaines + 44 internationales) scanné segment par segment de droite à gauche -> statut `city_approximate`.
  5. Sinon -> `unlocalized`.
- **Géocodage manuel Nominatim** : déclenché uniquement sur clic utilisateur unitaire (`GET https://nominatim.openstreetmap.org/search?format=json&limit=1&q=...`), résultat persisté dans `localStorage`.

## 4. STATUS WORKFLOWS & BUSINESS RULES

### 4.1 Cycle de Vie d'un Fournisseur (`Fournisseur.actif`)

```text
  [Création POST /api/fournisseurs]
                 │
                 ▼
         ┌───────────────┐
         │  actif = true │  (Actif / Éligible aux consultations et bons de commande)
         └───────┬───────┘
                 │  PATCH /api/fournisseurs/{id}/desactiver
                 │  ou DELETE /api/fournisseurs/{id} (204 No Content)
                 ▼
         ┌────────────────┐
         │ actif = false  │  (Inactif / Suspendu ; exclu par défaut de GET liste unpaginée)
         └───────┬────────┘
                 │  PATCH /api/fournisseurs/{id}/reactiver
                 ▼
         ┌───────────────┐
         │  actif = true │
         └───────────────┘
```

- **Règle d'exclusion par défaut (`FournisseurService`)** : si `actif` n'est pas fourni et `includeInactive != true`, les endpoints de listing filtrent par `actif = true`. En revanche, `GET /api/fournisseurs/{id}` retourne **toujours** le fournisseur quel que soit son statut afin que le microservice Commandes puisse résoudre les commandes historiques d'un fournisseur désactivé.
- **Règle d'immuabilité du statut sur `PUT`** : `PUT /api/fournisseurs/{id}` ne modifie jamais le champ `actif` (géré exclusivement via `/desactiver`, `/reactiver` ou `DELETE`).
- **Règle d'unicité de l'e-mail** : vérifiée à la création (`existsByEmailIgnoreCase`) et à la mise à jour (`existsByEmailIgnoreCaseAndIdNot`) après normalisation `trim().toLowerCase()`, ainsi que par contrainte SQL unique `fournisseurs_email_key` (`409 CONFLICT` en cas de doublon ou de course concurrente interceptée via `DataIntegrityViolationException`).

### 4.2 Cycle de Vie des Commandes (Interprété depuis `service-commandes` dans `orderStats.ts` & `CommandesDrawer.tsx`)

```text
  EN_ATTENTE ──▶ VALIDEE ──▶ RECEPTIONNEE ──▶ FACTUREE
       │            │
       └────────────┴──▶ ANNULEE
```

- **Règles d'agrégation financière (`orderStats.ts`)** :
  1. `ANNULEE` : exclue de **tous** les totaux financiers (`totalOrderedAmount`, `totalCommittedAmount`, `receivedOrInvoicedAmount`), mais conservée dans le décompte `cancelledOrders` et le calcul de `latestOrderDate`.
  2. `EN_ATTENTE` : incluse dans `totalOrderedAmount`, **exclue** de `totalCommittedAmount`.
  3. `VALIDEE` : incluse dans `totalOrderedAmount` et `totalCommittedAmount`.
  4. `RECEPTIONNEE` / `FACTUREE` : incluses dans `totalOrderedAmount`, `totalCommittedAmount` et `receivedOrInvoicedAmount` (et projetées dans l'onglet Réceptions ; seule `FACTUREE` est projetée dans l'onglet Factures).
  5. `paidAmount` est **toujours `null`** (règle d'intégrité : aucun décaissement n'est inféré sans le microservice Factures).

### 4.3 Algorithme de Notation Fournisseur (`scoring.ts`)

1. Si une note manuelle existe dans `localStorage['procuraflow-supplier-ratings'][id]`, elle prévaut (`score` entre `1.0` et `5.0`).
2. Sinon, score algorithmique déterministe : base `4.2`, bonus `+0.6` si `>= 3` commandes sans annulation (ou `+0.3` si `> 0` commande sans annulation), malus `-0.5 * annulees`, `+0.2` si `adresse.length > 10`, `+0.1` si `telephone` présent, `-1.0` si `!actif`, plus micro-variation déterministe `((id * 17) % 7) * 0.05`, borné dans `[2.5, 4.9]`.
3. **Statut dérivé** :
   - `score >= 4.5 && actif` -> **`Recommandé`** (`recommande`)
   - `score < 3.5 || !actif` -> **`Inactif`** (si inactif) ou **`Sous surveillance`** (`vigilance`)
   - Sinon -> **`Conforme`** (`conforme`).
4. **Fiabilité** : si `totalCmds > 0`, `Math.round((VALIDEE + RECEPTIONNEE + FACTUREE) / totalCmds * 100)` ; sinon `60%` si inactif, `100%` si actif.

## 5. NON-FUNCTIONAL & SECURITY DETAILS

### 5.1 Sécurité, Authentification & Validation

- **Authentification / Session / JWT / RBAC** : **Non implémenté.** Aucun mécanisme de connexion, hachage de mot de passe, expiration de jeton ou limitation de tentatives de connexion n'existe dans le projet.
- **Politique CORS (`CorsConfig.java`)** : autorise `/api/**` pour les origines `http://localhost:5173`, `http://localhost:3000`, `http://localhost:8080`, `http://127.0.0.1:5173` avec méthodes `GET, POST, PUT, PATCH, DELETE, OPTIONS`, tous headers `*` et `allowCredentials(true)`.
- **Hygiène des erreurs & exposition Actuator (`application.yml`, `GlobalExceptionHandler.java`)** :
  - `server.error.include-message: never`, `include-binding-errors: never`, `include-stacktrace: never`.
  - Actuator n'expose que `health,info` avec `show-details: never` et `probes.enabled: true`.
  - Réponses d'erreur JSON uniformisées via `ApiErrorResponse(timestamp, status, error, message, path, fieldErrors)` pour `400`, `404`, `405`, `409`, `502`, `503`, `500` (sans fuite de stacktrace SQL/Java en `500`).
- **Protection SQL & XSS** :
  - Requêtes JPA Criteria paramétrées ; motifs `LIKE` échappés via `escapeLikePattern` (échappement de `\`, `%`, `_` avec caractère d'échappement `\`).
  - Popups Leaflet dans `FournisseurMap.tsx` construites exclusivement par manipulation DOM sûre (`textContent`), prévenant les injections HTML/XSS sur les noms ou adresses fournisseurs.
- **Configuration Base de Données (`NeonJdbcUrlResolver.java`)** : supporte la conversion d'URL `postgresql://` / `postgres://` (avec identifiants intégrés extraits proprement vers `DataSourceProperties`) et impose `currentSchema` (défaut `schema_fournisseurs`).

### 5.2 Pagination, Filtrage, Tri & Performance

- **Pagination Serveur** :
  - Endpoint `GET /api/fournisseurs` avec `@Min(0) page` (défaut `0`) et `@Min(1) @Max(50) size` (défaut `10`, choix UI `10` / `25` / `50`, max strict `50`).
  - Tri appliqué en base via Spring Data `Sort` sur liste blanche : `ALLOWED_SORT_FIELDS = {"nom", "email", "createdAt", "updatedAt", "id", "actif"}` (tri insensible à la casse sur `nom` et `email`, puis bris d'égalité systématique par `id ASC`). Tout champ ou direction invalide renvoie `400 Bad Request`.
  - *Limitation connue* : l'option UI `Évaluation` (`rating-desc`) ne pouvant pas être triée par la BD (les notes manuelles étant dans `localStorage`), le frontend envoie `sort=actif,desc` au serveur et trie localement la page retournée ; pour les exports CSV/PDF et la vue Carte, il récupère la liste non paginée et trie l'ensemble côté client.
- **Résilience Réseau & Concurrence UI (`App.tsx`)** :
  - Annulation des requêtes obsolètes par `AbortController` + compteur de séquence (`requestSeqRef`, `mapRequestSeqRef`), évitant les conditions de concurrence lors de frappes rapides.
  - Debounce de `250ms` sur la recherche libre et mises à jour atomiques du state `SupplierQueryState` pour éviter les doubles requêtes API.
  - Timeouts `RestClient` vers le microservice Commandes : `connectTimeoutMs = 3000`, `readTimeoutMs = 5000`. Une réponse `404` sur `/api/commandes?fournisseurId={id}` est normalisée en liste vide `[]` ; une indisponibilité réseau / `503` / `504` lève `503 Service Unavailable`.
- **Optimisation Bundle & Rendu** :
  - Chargement différé (`lazy` / `dynamic import()`) de `FournisseurMap` (Leaflet), `jspdf` / `jspdf-autotable` (au clic Export PDF), et `xlsx` (uniquement lors de l'import d'un fichier tableur).
  - Animation d'entrée progressive (`.supplier-entrance` : translation `8px` -> `0`, durée `260ms` `cubic-bezier(0.22, 1, 0.36, 1)`, délai échelonné plafonné à `460ms` via `getStaggerDelayMs`) désactivée automatiquement lorsque `prefers-reduced-motion: reduce` est actif (`window.matchMedia` + règle CSS `@media (prefers-reduced-motion: reduce)`).
  - `ErrorBoundary` global interceptant les plantages React (notamment dus aux extensions navigateur modifiant le DOM) avec bouton `Rafraîchir l'interface`.
